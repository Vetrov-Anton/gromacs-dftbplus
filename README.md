# GROMACS + DFTB+ — QM/MM with boundary exclusions and selectable MM retention

This is a fork of the GROMACS/DFTB+ QM/MM interface (GROMACS 2021 line, DFTB+ coupling
by Kubař *et al.*) with three additions:

1. **Topological (1-2, 1-3, 1-4) exclusions of the QM–MM electrostatics** — the MM atoms
   covalently close to a QM atom can now be removed from (or scaled in) the external
   potential that enters the QM Hamiltonian. Consistently implemented for all
   electrostatic variants, including PME.
2. **A selectable MM-retention scheme at the QM/MM boundary** — `classic` (the historical
   GROMACS rule) or `amber` (only all-QM terms are dropped), chosen in `grompp`.
3. **A report from `grompp`** listing every force-field term that was removed around the
   QM region, split by interaction type and by how the term straddles the boundary.

Everything is driven by environment variables; no `.mdp` option and no `tpr` format change
is involved. With none of them set, the build behaves exactly like the original code.

## Installation

### GROMACS

Two container recipes ship with the repository. Both build DFTB+ 21.2 (with the API, tblite
and s-dftd3), PLUMED with libtorch, and this GROMACS in double precision with MPI.

**Docker:**

```bash
docker build -t gmx-dftbplus -f gmx_dftbplus_new.dockerfile .
```

**Apptainer / Singularity:**

```bash
apptainer build --fakeroot gmx_dftbplus.sif gmx_dftbplus_plumed_torch_openblas.def
```

Note that the `%environment` section of the definition file already sets
`GMX_QMMM_VARIANT=1` and `OMP_NUM_THREADS=1` inside the container.

### QMMMtools

The companion module for preparing the QM/MM topology (see the next section):

```bash
pipx install git+https://github.com/Vetrov-Anton/QMMMtools.git   # command line tool
pip  install git+https://github.com/Vetrov-Anton/QMMMtools.git   # import QMMMtools
```

pipx deliberately hides the package from your interpreter, so install it with `pip` as well
if you want `import QMMMtools` to work in a script or a notebook.

## Preparing a QM/MM topology: QMMMtools

A companion Python module, **[QMMMtools](https://github.com/Vetrov-Anton/QMMMtools)**, was
developed for this build. It carves a QM region out of a finished classical GROMACS system
and writes `qm.top`, `qm.gro`, `qm.ndx` and `dftb_in.hsd`.
It places hydrogen link atoms as two-body virtual sites, converts the QM–QM bonds to
connections (`funct 5`), derives the integer QM charge from the force field and
redistributes the remainder, and offers the boundary charge schemes
(`no` / `amber` / `RC` / `RCD` / `CS`) as well as the same MM-retention schemes described
below (`--mm-retention no|classic|amber`).

```bash
qmmmtools prepare -c npt.gro -p topol.top -e '@21313,21391,21408' \
    --solvate 3.0 --hsd --skpath ./3ob-3-1-ophyd/ --mixer anderson
```

Using it is not mandatory — a hand-built topology works — but the four output files and the
`qmmmtools check` consistency test are the intended entry point to everything below.

## 1. Exclusions at the QM/MM boundary (mdrun)

In the original code, **every** MM atom inside the cut-off contributes its full point charge
to the external potential of the QM Hamiltonian — including the MM atoms directly bonded to
a QM atom. The exclusions generated by `grompp` act only on the classical nonbonded
interactions and never reach the QM calculation. Since the boundary MM1 atom sits ~1.5 Å
from a QM atom (and even closer to its link atom), its unscreened charge over-polarizes the
QM density; this is what the various charge-shift schemes in the literature work around.

This build can instead reproduce the exclusion convention of the force field for the QM–MM
electrostatics as well. The bonded neighbour order cannot be recovered from the flat
`moltype->excls` list, so it is recomputed at mdrun start by a breadth-first search over the
chemical bonds, from every QM atom. The search sees the full connectivity: bonds inside the
QM region became `F_CONNBONDS` (still `IS_CHEMBOND`), and the bonds crossing the boundary are
left intact. The resulting per-pair scaling factors are re-mapped onto the short-range MM
list every time that list is rebuilt, and applied to both the potential and the gradients.

### `GMX_QMMM_NREXCL` — highest excluded bonded neighbour order

| value | effect |
|---|---|
| `0` (default) | no topological exclusions — the original behaviour |
| `1` | 1-2 pairs (directly bonded) removed from the QM Hamiltonian |
| `2` | 1-2 and 1-3 pairs removed |
| `3` | 1-2 and 1-3 removed, 1-4 pairs **scaled** with `fudgeQQ` |

Any other value is a fatal error. `3` matches the usual force-field convention (AMBER,
CHARMM, OPLS) and is the recommended setting for a link-atom QM/MM boundary.

### `GMX_QMMM_FUDGEQQ` — 1-4 scaling factor

Only relevant with `GMX_QMMM_NREXCL=3`. Defaults to the `fudgeQQ` of the force field taken
from the `tpr` (0.8333 for AMBER, 0.5 for OPLS, 1.0 for CHARMM). Set it explicitly to
override, e.g. `GMX_QMMM_FUDGEQQ=1.0` to keep the 1-4 QM–MM electrostatics unscaled while
still removing 1-2 and 1-3.

### PME

With `GMX_QMMM_VARIANT=1` the reciprocal-space part is evaluated on a grid over the full MM
list and cannot be scaled there. For every scaled pair the fraction `(1−s)` of its
reciprocal-space term `erf(βr)/r` is therefore subtracted analytically as a pair term, in
both the potential and the gradient; together with the scaled real-space term `s·erfc(βr)/r`
this reproduces exactly `s/r` for the pair. The correction is applied outside the cut-off as
well, because the reciprocal-space contribution is not cut off either, and it stays finite as
`r → 0` (`erf(βr)/r → 2β/√π`), so a link atom coinciding with an MM atom on the first step
does not blow up the correction.

mdrun prints how many pairs were removed and how many were scaled, e.g.

```
Topological exclusions applied to the QM/MM electrostatics (GMX_QMMM_NREXCL = 3).
  QM--MM pairs up to 1-3 removed from the QM Hamiltonian: 128
  1-4 QM--MM pairs scaled with fudgeQQ = 0.833333: 96
```

## 2. MM retention at the boundary (grompp)

Bonded force-field terms whose atoms lie in both regions have two conventions in use, and
this build lets you pick.

### `GMX_QMMM_BONDED_SCHEME` — read by **grompp**, not by mdrun

| value | rule |
|---|---|
| `classic` (default) | a bonded term is removed as soon as **all but one** of its atoms are QM (so a QM–QM–MM angle and a QM–QM–QM–MM dihedral go), because the QM calculation with the link atom is assumed to describe it; in addition the nonbonded and 1-4 interactions of the QM atoms with the link atoms are excluded. This is the historical GROMACS behaviour. |
| `amber` | only terms whose atoms are **all** QM are removed; every term with at least one MM atom is kept at the force-field level, and no exclusions involving link atoms are generated. Follows the QM/MM implementation of AMBER: the link atom is not the MM atom — different position, different mass — so its contribution is not equivalent to the force-field term, and the conformational behaviour of the boundary is better described by keeping the latter. |

Unknown values are a fatal error. `amber` also raises a `grompp` note, since with a
link-atom-capped QM region the QM contribution is then counted **on top of** the retained
force-field terms.

The scheme is resolved at preprocessing time and baked into the `tpr` — setting the variable
for `mdrun` has no effect, and mdrun prints a `NOTE` reminding you of that if it sees it set.
Note also that `amber` treats single-atom terms (position restraints) differently: `classic`
removes them unconditionally, `amber` only for QM atoms.

`GMX_QMMM_MIMIC` keeps using the same bonded rule as `amber` (MiMiC treats link atoms as
quantum atoms), which is why the two share a branch in the code.

If you prepared the topology with `QMMMtools --mm-retention classic|amber`, the terms are
already gone from the `.top` and this variable has nothing left to act on.

### The removal report

Whenever a system contains QM atoms, `grompp` now prints what it removed:

```
QM/MM: force-field terms removed with the 'amber' scheme, by interaction type:
  interaction                 all-QM     QM--MM    MM-only
  Bond                            211          0          0
  Angle                           382          0          0
  Proper Dih.                     514          0          0
  LJ-14                           298          0          0
  total                          1405          0          0
  all-QM  = every atom of the term is QM: described by the QM calculation
  QM--MM  = the term spans the QM/MM boundary
  MM-only = no QM atom in the term at all
No term spanning the boundary was removed: every force-field term with at least one MM atom is kept.
```

The middle column is the interesting one: it is exactly what the two schemes disagree about.
With `classic` it is non-zero and the message instead points at `GMX_QMMM_BONDED_SCHEME`.
Chemical bonds between two QM atoms are not lost but converted to connections
(`F_CONNBONDS`); removed 1-4 pairs are listed as well.

A warning about QM atoms in several molecule types is now issued for the `amber` scheme too
(previously only for `classic`).

### What `LJ-14` is, and why it is removed

`LJ-14` is the row of the report that surprises people most, so it is worth spelling out.

**In a plain MM force field.** Two atoms separated by exactly three bonds — the first and
the last atom of a torsion, `1-2-3-4` — are called a *1-4 pair*. Most force fields declare
`nrexcl = 3`, which means all pairs up to three bonds apart are excluded from the normal
nonbonded loop. If nothing else were done, the 1-4 atoms would then feel no nonbonded force
at all. So the force field puts a **special, scaled-down copy** of the interaction back, as
an explicit entry in the `[ pairs ]` section of the topology. That entry is what GROMACS
calls `F_LJ14`, and it is what the `LJ-14` row counts.

Two things about it are easy to get wrong:

* Despite the name, **each `[ pairs ]` entry carries both the 1-4 Lennard-Jones *and* the
  1-4 Coulomb interaction.** `F_COUL14` has no interaction list of its own in GROMACS
  (it is declared `def_nofc`) — the Coulomb-14 energy is computed from the same `[ pairs ]`
  list, with the electrostatic part multiplied by `fudgeQQ`. Removing one `LJ-14` entry
  therefore removes *both* 1-4 terms for that atom pair.
* The 1-4 pair term is **not** a leftover or a correction — it is part of the torsion
  parametrization. The dihedral potential and the 1-4 pair were fitted *together* against
  the same reference data, which is why the pair term cannot simply be deleted in ordinary
  MM work without breaking the torsion.

**At the QM/MM boundary.** Now consider a 1-4 pair in which **both atoms are QM**. DFTB+
computes the real, electron-mediated interaction between those two atoms explicitly, from
first principles — including everything the classical 1-4 term was a crude stand-in for. If
the `[ pairs ]` entry were left in the topology, that interaction would be counted twice:
once quantum-mechanically, once classically. So the entry is removed. This happens under
**every** scheme — `classic`, `amber` and MiMiC alike — for exactly the same reason that the
QM–QM bonds, angles and dihedrals are removed. Those pairs land in the **all-QM** column of
the report, and their count is usually the second largest after the dihedrals.

**Where the schemes differ** is the pair between a **QM atom and a link atom** (an MM atom
covalently bound to the QM region, "MM1"):

* `classic` removes it as well, on the assumption that the QM calculation with the link atom
  already describes the boundary. These pairs appear in the **QM--MM** column.
* `amber` keeps it. The link atom is a *hydrogen* sitting ~1.09 Å from the QM atom, not the
  real MM1 atom in its real position with its real mass, so what the QM calculation produces
  is not a substitute for the force-field term. The internal flag that marks link atoms is
  simply never set with this scheme, so only the QM–QM pairs are dropped, and the
  **QM--MM** column comes out zero.

In the source this is the loop `for (int i = F_LJ14; i < F_COUL14; i++)` near the end of
`generate_qmexcl_moltype()` in `topio.cpp` — which, given the enum order above, runs over
`F_LJ14` alone.

**Do not confuse this with `GMX_QMMM_NREXCL`.** Both use the phrase "1-4" and both involve
`fudgeQQ`, but they act on different things at different times:

| | `LJ-14` removal (this section) | `GMX_QMMM_NREXCL` (section 1) |
|---|---|---|
| when | `grompp`, written into the `tpr` | `mdrun`, every step |
| acts on | the classical `[ pairs ]` list of the MM force field | the MM point charges entering the **QM Hamiltonian** |
| affects | the MM energy term | how strongly the MM environment polarizes the QM density |
| pairs concerned | QM–QM (all schemes) and QM–link (`classic` only) | QM–MM, up to 3 bonds |
| Lennard-Jones | yes, removed together with the Coulomb part | **never touched** — `GMX_QMMM_NREXCL` is purely electrostatic |

The last row deserves emphasis: the QM atoms keep their Lennard-Jones parameters throughout,
and the QM–MM van der Waals interaction is handled by the classical force field in the normal
way, whatever you set `GMX_QMMM_NREXCL` to. Only the *charges* of the QM atoms are zeroed
(they are replaced by the QM density), and only the *charges* of nearby MM atoms are scaled
in the embedding potential.

## 3. QM/MM electrostatics variant (pre-existing, for reference)

| variable | meaning |
|---|---|
| `GMX_QMMM_VARIANT=0` | no electrostatic QM/MM interaction (vacuum QM) — the default when unset |
| `GMX_QMMM_VARIANT=1` | full PME treatment (requires a triclinic/`xyz` periodic system) |
| `GMX_QMMM_VARIANT=2` | switched cut-off |
| `GMX_QMMM_VARIANT=3` | reaction field |
| `GMX_QMMM_VARIANT=4` | shifted cut-off |
| `GMX_QMMM_PME_DIPCOR` | dipole (surface) correction for PME — currently disabled in the code, mdrun exits if set |

## 4. DFTB output files (mdrun)

Each of the following is set to an **integer stride in steps**; the file is opened in append
mode in the run directory on step 0 and written every *N* steps. Unset means no file. The
variables that describe the MM environment are ignored when `GMX_QMMM_VARIANT=0` (vacuum).

| variable | file | content |
|---|---|---|
| `GMX_DFTB_CHARGES=N` | `qm_dftb_charges.xvg` | Mulliken charges of the QM atoms, one row per written step |
| `GMX_DFTB_ESP=N` | `qm_dftb_esp.xvg` | electrostatic potential induced by the MM environment on each QM atom |
| `GMX_DFTB_QM_COORD=N` | `qm_dftb_qm.qxyz` | QM coordinates in XYZQ format (x, y, z, charge) |
| `GMX_DFTB_MM_COORD=N` | `qm_dftb_mm.qxyz` | coordinates and charges of the MM atoms **on the short-range list** |
| `GMX_DFTB_MM_COORD_FULL=N` | `qm_dftb_mm_full.qxyz` | coordinates and charges of **all** MM atoms |

`GMX_DFTB_MM_COORD_FULL` on a solvated system writes the whole box every *N* steps — pick a
large stride. Each variable prints a confirmation line at startup.

## Typical run

```bash
gmx() {
singularity run  --env GMX_QMMM_VARIANT=1 --env OMP_NUM_THREADS=1 --env GMX_QMMM_NREXCL=3   --nv -B /home/domain/data:/home/domain/data --pwd $(pwd) /home/domain/data/avetrov/build_dftb_gmx/new_gmx_dftb.sif /opt/gmx/bin/gmx $@
}

gmx grompp -f qm.mdp -p qm.top -n qm.ndx -c qm.gro -o qw.tpr -r qm.gro -maxwarn 4

gmx mdrun -deffnm qw -ntomp 1 -pin on -pinoffset 0 -v
```

with an `.mdp` containing

```
QMMM      = yes
QMMM-grps = QM
QMmethod  = RHF        ; grompp insists on a value, this build ignores it
QMbasis   = STO-3G     ; likewise
QMcharge  = -2         ; must equal Charge in dftb_in.hsd
QMmult    = 1
```

`dftb_in.hsd` must sit in the run directory. mdrun reads it once and overwrites the
coordinates every step, so the numbers in `Geometry` do not matter — but the atom **count**
and **order** do.

### Choosing the settings

* `GMX_QMMM_BONDED_SCHEME=classic` + `GMX_QMMM_NREXCL=0` reproduces the original code
  exactly — use it to reproduce older results.
* `GMX_QMMM_BONDED_SCHEME=amber` + `GMX_QMMM_NREXCL=3` is the AMBER-like combination: the
  boundary geometry is held by the retained force-field terms, and the MM charges that the
  force field would have excluded do not polarize the QM density either.
* Mixing them (`classic` + `NREXCL=3`) is legitimate but means the boundary bonded terms are
  described by the QM calculation while the close MM charges are screened out — check the
  `grompp` table and know what you are asking for.
